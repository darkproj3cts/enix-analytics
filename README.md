# Коммерческая аналитика WB-селлера

Прототип системы управленческого учёта для селлера Wildberries в категории женской одежды. Единая модель данных: заказы → выкупы → возвраты → финансовый отчёт WB → остатки → выплаты → реклама → себестоимость по партиям (FIFO).

Данные синтетические, по структуре повторяют выгрузки из WB Seller API.

[enix-analytics.streamlit.app](https://enix-analytics.streamlit.app)

Если ссылка открывается с задержкой или с экраном «get this app back up» — Streamlit Cloud усыпляет free-apps при простое. Нужно 30–60 секунд на пробуждение.

## Стек

- **Данные:** DuckDB (локальная OLAP-база)
- **ETL и генерация:** Python 3.13 + pandas + numpy
- **Расчётный слой:** чистый SQL, 8 витрин с оконными функциями (включая FIFO-списание без курсоров)
- **BI:** Streamlit + Plotly + AgGrid, матовая тема в стиле Linear/Notion
- **Структура:** Raw → Staging → Core → Marts → BI

## Что считает система

| Витрина | Назначение |
|---|---|
| `v_fifo_cogs` | Себестоимость каждой продажи по FIFO через оконные функции |
| `v_pnl_sku_day` | P&L по SKU по дням: от выручки после СПП до валовой маржи |
| `v_unit_economics` | Юнит-экономика на заказ и на выкуп, ДРР, ROMI, тир эффективности рекламы |
| `v_gmroi` | GMROI с классификацией SKU (отлично / норма / слабо / паразит) |
| `v_turnover` | Оборачиваемость, прогноз даты OOS, подсветка неликвида |
| `v_margin_leak` | Разложение потерь по 8 причинам (комиссия, логистика, хранение, реклама) |
| `v_reconciliation` | Понедельная сверка выплат WB с расчётным счётом |

| Таблица | Строк | Аналог в WB API |
|---|---:|---|
| `sku` | 85 | карточки товара |
| `cogs_batch` | 514 | 1С / Google Sheets |
| `orders` | 30 344 | `/api/v1/supplier/orders` |
| `sales` | 29 914 | `/api/v1/supplier/sales` |
| `returns` | 27 164 | производная из orders/sales |
| `finance_wb` | 87 828 | `/api/v5/supplier/reportDetailByPeriod` |
| `stock_daily` | 4 505 | `/api/v3/stocks` + snapshot |
| `payments` | 52 | банковская выписка |
| `ads_daily` | 30 344 | рекламный ЛК WB |

**Период:** 12 месяцев (2025-11-01 — 2026-10-28).
**Выручка:** 370 млн ₽ после СПП, выкуп 78,5%, ДРР 15%.
**Калибровка:** реалистичная сезонность термобелья (пик декабрь-январь), разный % выкупа по размерам (XS/XL ниже на 7-8 п.п.), 25% рекламных кампаний умышленно убыточные для демо витрины «ROMI < 0».

## Ключевые инсайты в данных

- **P&L:** общая маржа 17% (62,8 млн ₽ при выручке 370 млн ₽), в топ-10 убыточных — размеры XS/XL моделей-«массовки».
- **GMROI:** 6 SKU-паразитов замораживают 1,5 млн капитала с минусовой маржой.
- **Реклама:** 25,6 млн ₽/год тратится на SKU с «дорогой» или «убыточной» рекламой — кандидаты на отключение.
- **Оборачиваемость:** 27 SKU в глубоком неликвиде (> 180 дней), 7 SKU — риск OOS в ближайший месяц.
- **Сверка выплат WB vs банк:** расхождение стабильно ±0,2%, аномалии ловятся автоматически.

## Запуск локально

Нужен Python 3.11+ и pip.

```powershell
# Клонируем репо
git clone https://github.com/USER/enix-analytics.git
cd enix-analytics

# Виртуальное окружение
python -m venv .venv
.venv\Scripts\Activate.ps1

# Зависимости
pip install -r requirements.txt

# Генерация данных и SQL-витрин (один раз)
python scripts\generate_data.py
python scripts\apply_views.py

# Запуск дашборда
streamlit run app\main.py
```

Открывается на http://localhost:8501.

## Параметры генерации

Все ключевые параметры в `scripts/generate_data.py` в блоке «ПАРАМЕТРЫ ГЕНЕРАЦИИ»:

- `WB_COMMISSION_PCT = 0.245` — комиссия WB для одежды
- `SELLER_COST_PCT = (0.26, 0.36)` — доля себестоимости от цены
- `MODEL_BUYOUT_BASE` — средний % выкупа по категориям
- `SIZE_BUYOUT_DELTA` — отклонение по размерам
- `SEASON_MULT` — сезонность по месяцам
- `TARGET_ANNUAL_REVENUE = 450_000_000` — целевой масштаб
